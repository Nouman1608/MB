# Marlbridge audit - tier-blind corrections, and how far to trust these counts

*Correction audit, round three. No resources were read.*

## First, the triage was reconciled

Q353 flagged that the triage is a snapshot and had drifted by five findings. Fetching the
full window shows the drift is wider: decision-log entries **D-192 through D-199**, all
committed on 13–14 September, close around 124 findings.

| | |
|---|---|
| triage entries | 255 |
| closed since generation | 13 |
| in a partly-closed range, kept and flagged | 8 |
| **still open, still to audit** | **234** |

Three commits carry qualifiers I've reproduced rather than flattened — D-196 says "E712–E748
(nearly all)" without saying which are left, and D-193/D-194 mark Q249 and E693 "partial".
Those eight stay in the working set. Dropping a finding on an ambiguous commit message would
be the same error this workstream exists to catch. Deferrals (E757–E759, E763, Q291 and
others) are explicitly **not** treated as closed.

## Q354: nine corrections that are unsafe twice over

Of 234, **68 carry a correction whose finding establishes a tier and whose fix doesn't carry
it forward.** That alone is a scope problem. But 31 of the 68 concern a **two-column
Core/Supplement or Core/Extended layout** — the exact geometry U65 proved collapses when a
syllabus is extracted as linear text, emitting both tier headings before the body regardless
of which column the body occupies.

**Nine of those 31 instruct a corrector to add content.** Those nine fail in two independent
ways at once:

1. The tier recorded in the finding may be **backwards**, because it was established by
   reading order rather than column position.
2. **No tier travels with the correction**, so whatever is added lands at whatever tier the
   target file happens to carry.

One of the nine is a chemistry outcome on a syllabus in the very family where the collapse was
demonstrated, and its correction is to add an explanatory paragraph with no tier attached. If
that outcome is Supplement and the file is Core, the addition puts unassessed material in front
of a Core candidate — and if the tier was read backwards, the same correction removes the error
in one direction while creating it in the other.

**These nine should not be worked** until each tier is re-established by column position. The
other 59 need only the tier carried down into the fix.

## Q355: a fifth of that group was my screen's error

Before quoting 86 as a number I inspected it. **18 of the 86 (21%) were not tier-blind at
all** — the correction did carry the tier, in vocabulary my regex didn't know:

- the bare word **"tier"** (*"Replace every tier reference with…"*)
- the GCSE abbreviations **HT** and **FT** (*"Restore the (HT only) and (physics only) tags"*)
- **Foundation** on its own
- a qualification-specific **B marker** for co-teachable content

That is the **third screening defect found in this workstream in one sitting**, all three
caught by inspecting flagged items rather than by any check built into the screens:

| # | defect | effect |
|---|---|---|
| 1 | case-insensitive `\bAS\b` matching the ordinary word "as" | inflated one group from 89 to 301 |
| 2 | a snapshot directory trusted as current without reading its commit | produced Q348, which needed Q350 to correct it |
| 3 | tier vocabulary too narrow | 21% false positives in this group |

**The honest implication:** the published figures of 255 flagged and 234 reconciled rest on the
same seven regular expressions, and neither has been audited this way. **Treat the flagged sets
as a reading list, not a measurement**, until each group has been inspected as this one was.
Every count this workstream publishes from here should carry a measured false-positive rate
beside it.

## Q354 - Nine corrections add content to a tiered resource without naming a tier, on syllabuses whose tiers were read the way that collapses [Questionable claim, High]

- **Files:** `metal-properties-and-reactivity`, `a-physics-oscillations`, `a-level-computer-science-information-representation`, `a-world-history-modern-europe-revision-notes`
- **Where:** Tier-blind corrections on two-column syllabuses
- **Locate by:** `title: "Metal Properties and Reactivity"`

**What is wrong.** Sixty-eight open confirmed errors carry a correction whose finding establishes a tier and whose fix does not carry it forward. Thirty-one of those concern a two-column Core and Supplement or Core and Extended layout, which is the geometry an earlier finding of this audit proved collapses when the syllabus is extracted as linear text: both tier headings are emitted before the body regardless of which column the body occupies, so content can read as the wrong tier. Nine of the thirty-one go further and instruct a corrector to add content. Those nine are unsafe in two independent ways at once. The tier recorded in the finding may be backwards, because it was established by reading order rather than by column position, and no tier travels with the correction, so whatever is added lands at whatever tier the target file happens to carry. One of the nine is a chemistry outcome on a syllabus in the family where the collapse was demonstrated, and its correction is to add an explanatory paragraph with no tier attached; if that outcome is Supplement and the file is Core, the addition puts unassessed material in front of a Core candidate, and if the tier was read backwards the same correction removes the error in one direction and creates it in the other. Note for correction: these nine should not be worked until the tier of each is re-established by column position, which is the outstanding task recorded against the column defect, and the remaining fifty-nine tier-blind corrections need only the tier carried down into the fix.

**Fix.** Hold the nine until each tier is re-established by column position, and carry the tier into the fix of the other fifty-nine.

## Q355 - A fifth of one screening group was the screen's own error, the third such defect in this workstream in one sitting [Questionable claim, Medium]

- **Files:** `a-physics-oscillations`
- **Where:** Reliability of the correction-audit screens
- **Locate by:** `title: "Oscillations"`

**What is wrong.** This workstream screens findings by regular expression and publishes counts from the result, so the reliability of the screens is the reliability of the counts. Three defects have now been found in them in a single sitting, all by inspection of the flagged items rather than by any check built into the screens themselves. The first was a case-insensitive match on a two-letter qualification abbreviation that also matches an ordinary English word, which inflated one group from eighty-nine to three hundred and one. The second was not a regular expression at all but the same class of error: a snapshot directory trusted as current without its commit being read. The third is measured here. The tier screen tests whether a correction carries a tier using the vocabulary it uses on the observation, and that vocabulary is too narrow: boards write the tier as the bare word tier, as the abbreviations HT and FT, as Foundation alone, and in at least one qualification as a letter marker for co-teachable content. Eighteen of eighty-six flagged corrections did carry the tier in one of those forms and should never have been flagged, a false-positive rate of twenty-one per cent. Note for correction: the published figure of two hundred and fifty-five flagged findings, and the reconciled two hundred and thirty-four, both rest on the same seven regular expressions and neither has been audited this way; the flagged sets should be treated as a reading list and not as a measurement until each group has been inspected as this one was.

**Fix.** State a measured false-positive rate beside every count this workstream publishes, and inspect each signature group before quoting its size.
