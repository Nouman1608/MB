# Marlbridge audit — a truncated list read as a complete one

*Repair verification, round four. Short. The subject is a wrong claim this audit made, which
the repair instance caught before it reached anything published.*

---

## What happened

While confirming that the mark-scale regression had been repaired, this audit fetched the
changed-file list of the repairing commit `01f08fc`, saw none of the five MYP Language
Acquisition resources in it, and reported that the fix might have arrived in some other
commit.

**That was wrong, and the mechanism is worth naming precisely.**

The list held **exactly 30 entries**, sorted alphabetically, ending at:

```
src/content/resources/ib-dp-mathematics-ai-statistics-probability-revision-notes.md
```

`ib-myp-language-acquisition-*` sorts immediately after `ib-dp-mathematics-*`. The five files
were just past the cut. **30 is the page size of the interface, not a property of the commit.**

Confirmed by a second route that is addressed differently — the file's own commit history,
which lists `01f08fc` directly.

---

## How it was caught

The repair instance checked the claim against that history **before** acting on it, found the
repairing commit present, and reported back — rather than amending a correct ledger to match a
wrong correction. That is the right response to an incoming correction from another instance,
and it is the same discipline this audit asks of the repair work.

Its account of the *mechanism* differs from the one above: it attributed the truncation to an
abbreviating summary rather than to a page size. The difference does not matter. Its
conclusion was right and this audit's was not.

One symmetrical note, offered in the same spirit: its statement that *exactly two commits have
ever touched that file* is one short — `18ca8634` created it on 2 September. Immaterial to the
point it was making, which stands.

---

## The reusable part

**This audit already holds a test for exactly this hazard, in another medium.**

U68's terminal-marker test exists because an extraction of a specification that stops early
looks *identical* to one that is complete — no error, no gap, just an ending. Completeness is
therefore established by reaching the document's own closing matter, never by length and never
by the absence of a failure.

**A paginated tool result has precisely the same property, and there was no equivalent check
for it.**

The control:

> A result whose length is exactly a round number — 30, 100, 250 — is truncated until
> something else says otherwise. Especially if it is sorted and stops mid-alphabet. And a
> **negative** claim about a list ("X is not in it") must be confirmed by a second route
> addressed differently, because a list that ended early and a list that genuinely omits
> something are indistinguishable from the inside.

This is the third instance in this round of an incomplete or stale reading carried into a
claim — after the stale snapshot (Q350) and the stale conclusion (Q370) — and the **first of
the three to be caught before publication rather than after.**

Nothing published required correcting: the wrong sentence never reached an artefact.

## Q371 - A tool result truncated at its page size was read as a complete list, and the wrong conclusion drawn from it was caught by the repair instance before it reached anything published [Questionable claim, Medium]

- **Files:** `ib-myp-language-acquisition-syllabus-guide`
- **Where:** Method for reading a tool result
- **Locate by:** `independently weighted, each worth an equal 32 marks, so no single`

**What is wrong.** While confirming that the mark-scale regression had been repaired, this audit fetched the changed-file list of the commit that repaired it and reported that the list contained none of the five resources in question, suggesting that the fix might have arrived in some other commit. That was wrong. The list held exactly thirty entries, sorted alphabetically, ending at a mathematics revision-notes file; the five files in question sort immediately after that point and were therefore just beyond the cut. The number thirty is the page size of the interface, not a property of the commit. The repair instance checked the claim against the file own commit history before acting on it, found the repairing commit present there, and reported back rather than adjusting its own records to match a wrong correction. Its own account of the mechanism differs, attributing the truncation to an abbreviating summary rather than to a page size, and the difference does not matter: the conclusion it reached was right and the one recorded here was not. Its statement that exactly two commits have ever touched the file is itself one short, the file having been created by a third, earlier commit, which is immaterial to the point it was making. Note for correction, and it is the reusable part. This audit already holds a test for exactly this hazard in another medium: an extraction of a specification that stops early looks identical to one that is complete, so completeness is established by reaching the document own closing matter rather than by length or by the absence of an error. A paginated tool result has the same property and this audit had no equivalent check for it. A result whose length is exactly a round number, and especially one that is sorted and stops mid-alphabet, should be treated as truncated until a second route says otherwise. This is the third instance in this round of an incomplete or stale reading carried into a claim, and the first of the three to be caught before publication rather than after.

**Fix.** Treat any tool result of exactly a round length as truncated until confirmed, and confirm a negative claim about a list by a second route that is addressed differently - a file history rather than a commit file list, for instance. Do not conclude from a list that something is absent when the list may have ended early.

**Evidence.** Commit history of the MYP Language Acquisition syllabus guide, which lists the D-211 fix commit, the D-202 regression commit, and the commit that created the file - https://github.com/Nouman1608/MB/commits/main/src/content/resources/ib-myp-language-acquisition-syllabus-guide.md
