# Marlbridge audit — a finding withdrawn, and the reason it was wrong

*The repair instance rejected E901 and was right. Verifying it exposed a structural defect
behind three of the four stale claims this round.*

---

## E901 is withdrawn

It claimed that all six Islamiyat 2058 resources declare the closed 2024–2025 series, and
that none carries any note telling a reader newer cycles exist. **Neither half is true.**

All eight files were read on `main`:

| | |
|---|---|
| resources that exist | **8** (the audit's ledger knows 6) |
| declaring **2026–2027** | **7** |
| declaring 2024–2025 | 1 |
| carrying an explicit disclosure paragraph | 4, **including the 2024–2025 one** |

The single file still on the closed series says so plainly:

> **Which edition this guide covers:** this guide follows the **2024-2025 syllabus**, which
> has since closed. Cambridge has published two further cycles for 2058 — a 2026-2027
> syllabus … and a 2028 syllabus. The qualification itself is live and has not been withdrawn
> or renumbered. Check with your centre which cycle you are entered for…

**And it was not merely overtaken.** The most recent commit touching
`o-level-islamiyat-paper-1.md` is **D-194, 13 September** — *two days before E901 was
published*. The finding was wrong when it was written.

---

## The root cause, which is bigger than the finding

**The resource ledger that every corpus-wide sweep of this audit runs over is built from the
frozen baseline snapshot `ee1b341f`, not from `main`.**

`cycle_coverage.py` read a `syllabus_series` field as it stood weeks ago and reported it as
the present state of the site. The same ledger holds **6** resources for this code where the
corpus holds **8** — the identical defect seen from the other side, and it confirms the
file-count discrepancy D-206 reported about two other subjects, which this audit recorded as
unchecked and then never checked.

This explains three of the four stale claims in this round. They were not four separate
lapses; three share one structural cause.

### Consequence for Q367's register

**The 22-code register of closed examination windows is derived from that ledger. It describes
the baseline, not the site.** Some of the 21 codes listed as ending 2026 may already have been
retargeted, exactly as this one was.

> **Nothing in that register should be worked until it has been re-based against `main`.**

The same caution applies to `sibling_exposure.py` and `dup_pairs.py`, which read the same
ledger.

### Durable fix

`cycle_coverage.py` now prints this before any result:

```
==========================================================================
THIS READS THE FROZEN BASELINE LEDGER, NOT THE CURRENT BRANCH.
Ledger commit: ee1b341f31596dfb99cbb1b9136ad8e6d3016162
Every syllabus_series value below is as it stood at that commit. Resources
retargeted since then still appear here on their OLD series. A finding was
published from this script and had to be withdrawn for exactly that reason
(Q372): seven of eight resources for one code had already been moved to the
live cycle two days before the finding was written.
RE-BASE AGAINST main BEFORE WORKING ANY ROW.
==========================================================================
```

---

## How it was caught

The repair instance read all eight files live before amending its ledger, and rejected the
briefing rather than acting on it. That is the second time in two rounds it has declined to
change a correct record to match a wrong correction — and both times it was right.

This is the **fourth** stale-claim instance this round, and the first where the cause turned
out to be structural rather than a single lapse. The three rules already published — a finding
is a timestamp not a status; a flag is a document to open; confirm a negative by a second
route — were all necessary and none of them was sufficient, because none of them asks *which
commit the underlying data describes.*

## Q372 - A confirmed error of this audit is withdrawn, and the register that produced it is built on the frozen baseline rather than the current branch [Questionable claim, High]

- **Files:** `o-level-islamiyat-paper-1`, `o-level-islamiyat-paper-2-practice`
- **Where:** The Islamiyat finding, and every corpus-wide sweep this audit has run
- **Locate by:** `title: "O Level Islamiyat: Paper 1 (Cambridge 2058)"`

**What is wrong.** The confirmed error this audit published against the Islamiyat resources of one code is withdrawn. It asserted that every resource of that code declares a syllabus series whose last examination was in a year now passed, and that none of them carries any note telling a reader that newer cycles exist. Neither half is true of the corpus. Eight resources of that code exist, seven declare the series covering the two following examination years, and the eighth declares the closed series and carries an explicit paragraph stating that the series has closed, naming both later cycles, recording that the qualification is live and not withdrawn, and telling the reader to confirm with their centre which cycle they are entered for. The repair round that did this landed two days before the finding was published, so the finding was wrong when it was written and not merely overtaken. The root cause is larger than the finding and explains three of the four stale claims recorded in this round. The resource ledger that every corpus-wide sweep of this audit runs over is built from the frozen baseline snapshot taken at the start of the audit, not from the current branch. The sweep that produced the finding therefore read a series field as it stood weeks ago and reported it as the present state. The same ledger holds six resources for this code where the corpus holds eight, which is the same defect seen from another side and confirms a discrepancy a repair round had already reported about two other subjects and this audit had left unchecked. Note for correction, and it is the consequence that matters: the register of twenty-two codes on closed examination windows is derived from that ledger and must be treated as describing the baseline until it is rebuilt against the current branch. Some of the twenty-one codes it lists as ending this year may already have been retargeted, exactly as this one was. Nothing in that register should be worked from until it has been re-based.

**Fix.** Withdraw the confirmed error. Re-base the cycle-coverage register against the current branch before any of it is worked, and state on the register which commit it describes. Rebuild the resource ledger from the current branch, or label every sweep that reads it as describing the baseline, because a sweep that silently reports the state of a snapshot as the state of the site will keep producing findings that were wrong when written.

**Evidence.** The eight Islamiyat 2058 resources read on branch main: seven declare the 2026-2027 series and the eighth declares 2024-2025 with an explicit paragraph naming both newer cycles - https://github.com/Nouman1608/MB/tree/main/src/content/resources

**Evidence.** Commit history of o-level-islamiyat-paper-1.md, whose most recent change is D-194 on 13 September, two days before the withdrawn finding was published - https://github.com/Nouman1608/MB/commits/main/src/content/resources/o-level-islamiyat-paper-1.md
