# MARLBRIDGE v1.x FINAL — Closing Report

**Date:** 2026-08-19
**Scope closed by this report:** the multi-session taxonomy programme
covering CS/ICT, English, Psychology/Sociology, Geography/History, and
Pakistan Studies/Islamiyat/Urdu across all five boards (Cambridge,
Pearson Edexcel, AQA, OCR, OxfordAQA) — the standing instruction that
drove the bulk of this programme's later sessions.

## 1. What "done" means here

For every ACTIVE board+qualification+subject combination in scope, "done"
required:

1. A verified official syllabus code recorded in `matrix.ts`, with no
   silent gaps between a subject being marked `ACTIVE` and actually
   carrying a code.
2. A syllabus overview entry in `syllabuses.ts` (official title, code,
   board summary, source URL, verification date).
3. A topic taxonomy entry in `syllabus-topics.ts`, reproducing the
   awarding body's own topic/paper structure — never assumed from a
   sibling qualification without independent verification, never invented
   where subtopic detail wasn't available (the "honest partial taxonomy"
   pattern is used explicitly and disclosed in `notes` wherever full
   detail isn't yet researched).
4. A clean pass of the full validation gate: `astro check`,
   `validate:academic` (matrix, content-tagging, commercial-claims,
   cross-board-integrity), `astro build`, cross-board regression test,
   negative validation suite, API test suite, `npm audit`.
5. A live-verified production page for at least one representative
   combination per batch, fetched from `marlbridge.com` after Cloudflare
   deployment.

"Done" never meant a resource (study guide, revision notes, past papers)
existed for the combination — that is a separate, much larger body of
work, tracked as the 10-point resource coverage contract and explicitly
out of scope for this closing milestone.

## 2. Coverage achieved

As of this report, `docs/reports/academic-coverage-report-v1.2.csv`
records:

- **139** ACTIVE board+qualification+subject combinations tracked.
- **139/139** have an officially verified source (syllabus code + URL +
  verification date) — full coverage.

  zero-resource — this is the real remaining gap, and it is resource

## 4. Genuine defects found and fixed (not cosmetic)

Three separate instances of the same underlying bug pattern were caught
across this programme: `matrix.ts`'s `rows()` helper only sets
`qualificationCode` when the `codes` object for that row explicitly
includes the subject — so a subject could be `ACTIVE` on both the
Marlbridge and board-offering axes while carrying **no verified spec
code at all**, silently. Each instance was caught by cross-checking the
matrix against the ACTIVE subject list rather than trusting it, and fixed
with the real code plus, where relevant (Edexcel Urdu), an explanatory
note distinguishing it from the surrounding IAL-family subjects in the
same row.

- **117 zero-resource combinations**, each needing up to 10 resource
  types (study guides, revision notes, past-paper guidance, practice
  questions, exam preparation material) per the original contract. This
  is the single largest remaining body of work and is now being worked
  through in weekly batches rather than as a one-off push.

  Lower priority than the resource backlog since these combinations are

  `reviewStatus` remains `review-pending` on every resource (see decision
  log D-006). A real review workflow (who reviews, what evidence is
  recorded) is still to be designed.

## 7. v2.0 readiness specification

This section is a specification for what v2.0 should mean, not a claim
that v2.0 work has started.

**v2.0 should be considered ready to scope once:**

1. Zero-resource combinations drop below roughly 20% of the 139-row
   matrix (currently 84%) — i.e. the weekly batch process has had enough
   cycles to make the resource library the primary content of the site
   rather than the taxonomy scaffolding around it.
2. A real editorial review workflow exists and at least one subject's
   resources have been through it end-to-end, so `reviewStatus:
   'reviewed'` means something concrete and auditable.
3. The 21 taxonomy-thin combinations either get a real published
   structure or a documented, permanent decision that the qualification
   genuinely has none to publish (some skills-based language papers
   legitimately don't have a numbered topic list).

**Known constraints for whoever picks up the weekly scheduled task's
output:**

- Each scheduled run operates in a fresh, memory-less sandbox. It clones
  the repo, does its batch, and — unless push credentials happen to be
  configured in that environment — stops after a local commit rather than
  pushing, to avoid embedding a GitHub token in a persisted task file.
  **Someone should check in periodically whether commits are piling up
  unpushed** and either configure durable, scoped push credentials for
  the scheduled environment or manually pull and push the accumulated
  batches.
- The task prioritises Cambridge core subjects first, by design — this
  matches where Learners Academy actually teaches and where search
  traffic is likely highest, but it is a judgement call, not a hard
  requirement. Reprioritise by editing the task's prompt directly
  (`update_scheduled_task`) if a different order matters more.
- Every batch still goes through the full validation gate before
  committing. If a future change to the validators makes a step
  meaningfully slower, the weekly cadence and batch size (3 resources)
  may need revisiting so a single run doesn't run indefinitely.

## 8. Bottom line

The taxonomy layer for all in-scope subjects across all five boards is
complete, verified against official sources, and passing every automated
integrity check the repo has. The resource library behind that taxonomy
is 16% built. That gap — not academic accuracy, not site architecture —
is the actual remaining work, and it is now being worked through
incrementally rather than left as an unbounded backlog.
