Work through the list without notes. If you cannot do a statement, follow the pointer, then come back. Guide = the [study guide](/advanced-course-resources/computer-science-principles/3-13-developing-procedures-study-guide/); Practice = the [practice questions](/advanced-course-resources/computer-science-principles/3-13-developing-procedures-practice/).

## Understanding

- I can define procedural abstraction as naming a process so it can be used without knowing how it works *(Guide: Procedural abstraction; Practice: Question 1)*
- I can list ways procedural abstraction manages complexity *(Guide: Procedural abstraction; Practice: Question 6)*
- I can define modularity *(Guide: Procedural abstraction; Practice: Question 6)*
- I can explain why parameters allow reuse *(Guide: Procedural abstraction; Practice: Question 2)*

## Skills

- I can write a procedure with parameters, with and without a RETURN *(Guide: Writing a procedure; Practice: Question 8)*
- I can refactor repeated code into one general procedure *(Guide: Worked example 1; Practice: Question 2)*
- I can write a procedure that takes a list parameter and returns a result *(Guide: Worked example 2; Practice: Question 4)*
- I can reuse one procedure inside another *(Guide: Worked example 2; Practice: Question 8)*

## Reasoning

- I can decide whether a procedure should return or display a value *(Guide: Writing a procedure; Practice: Question 5)*
- I can explain why a procedure's internals can change without notifying its users *(Guide: Changing the inside without changing the outside; Practice: Question 3)*
- I can write the four-part explanation of how a procedure manages complexity *(Guide: Worked example 2; Practice: Question 9)*
- I can state where an immediate RETURN is useful and how it simplifies nested conditionals *(Guide: Worked example 1; Practice: Question 7)*

When every line is secure, move on. The revision notes are here: [revision notes](/advanced-course-resources/computer-science-principles/3-13-developing-procedures-revision-notes/).
