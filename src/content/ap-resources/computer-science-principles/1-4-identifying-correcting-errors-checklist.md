Work through the list without notes. If you cannot do a statement, follow its link, then come back. Guide = [study guide](/advanced-course-resources/computer-science-principles/1-4-identifying-correcting-errors-study-guide/); Practice = [practice questions](/advanced-course-resources/computer-science-principles/1-4-identifying-correcting-errors-practice/).

## Understanding

- I can define syntax, logic, run-time and overflow errors and give an example of each. *(Guide: "What is an error, and how do we know?"; Practice Q1, Q2, Q6)*
- I can explain that expected outputs come from the requirements. *(Guide: "Testing: defined inputs and expected outputs"; Practice Q3)*
- I can explain why passing some tests does not prove a program correct. *(Guide: Worked example 1; Practice question 10)*
- I can list five ways to find errors and say what each does. *(Guide: "Finding the error: five techniques"; Practice Q5)*

## Skills

- I can build a trace table for a loop and read the output from it. *(Guide: Worked example 2; Practice Q4, Q9)*
- I can design test cases with expected outputs, including boundaries and extremes. *(Guide: Worked example 1; Practice Q3, Q7)*
- I can correct a condition or loop count and retest. *(Guide: Worked examples 1 and 2; Practice Q8, Q9)*

## Reasoning

- I can name the error type from a described symptom. *(Guide: Figure 1; Practice Q1, Q2, Q6)*
- I can find the input that exposes a boundary error such as `>` instead of `>=`. *(Guide: Worked example 1; Practice Q3, Q8)*
- I can justify why a set of tests is or is not good enough. *(Guide: Worked example 1; Practice Q7 and question 10)*
