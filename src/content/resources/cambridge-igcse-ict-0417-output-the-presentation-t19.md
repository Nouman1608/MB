"Output the presentation" is the last content row of Topic 19 in the Cambridge IGCSE ICT 0417 syllabus. The guidance has two parts. You must **display** the presentation for a variety of purposes, including as a **looped on-screen carousel** and as a **presenter-controlled** show. You must also **print** it in a variety of layouts, including **full page slides**, **presenter notes** and **handouts**. This guide explains how each output is set up, how to choose the right one for a purpose and how to work out timings and page counts, which are common in both practical and theory questions.

For an overview of the whole topic, see the [Presentations study guide](/resources/cambridge-igcse-ict-presentations-study-guide/). ## Displaying the presentation

### Looped on-screen carousel

A carousel runs **by itself**, slide after slide, and starts again from the first slide when it reaches the end. It is used where nobody is presenting: a reception area, a shop window, an exhibition stand or a screen in a school corridor. To set it up:

1. **Set slide timings**: each slide advances automatically after a set number of seconds. Give every slide the time the task states; check none is left on "on mouse click" only.
2. **Set the show to loop**: in the slide show set-up options, choose to loop continuously until the Esc key is pressed. Many packages also offer a kiosk mode that loops automatically and ignores most clicks, so passers-by cannot stop the show by accident.
3. **Use the timings**: make sure the show is set to use the slide timings, not manual advance.
4. **Check effects**: transitions should be consistent, and audio should only play if the task wants it, because repeated sound in a public area quickly irritates people.

### Presenter-controlled show

In a presenter-controlled show the **speaker decides** when to move on, with a mouse click, a key or a remote. It is used for a lesson, a talk or a meeting, where the speaker may pause for questions, go back a slide or jump to another slide using hyperlinks and action buttons. Set the show to be presented by a speaker and to advance manually. Slide timings, if any were set, should not be used, or the slides may move on while the speaker is still talking. Many packages provide a presenter view on a second screen that shows the presenter notes and the next slide while the audience sees only the current slide.

### Choosing the display method

| Situation | Suitable output | Reason |
|---|---|---|
| Hotel reception screen showing facilities all day | Looped carousel | No presenter; runs and repeats unattended |
| Teacher explaining a new topic | Presenter controlled | Teacher sets the pace and can stop for questions |
| Exhibition stand that a salesperson sometimes talks over | Carousel between talks, presenter controlled during talks | The same file can be set up for either |
| Sales pitch to a client | Presenter controlled | The speaker may skip or revisit slides depending on questions |

### Timing calculations

Hidden slides are skipped in the show, so they add no time. For example, a carousel has 15 slides, three of which are hidden, and each slide is shown for 12 seconds.

- Slides shown: 15 − 3 = 12.
- Time for one loop: 12 × 12 = 144 seconds, which is 2 minutes 24 seconds.
- Complete loops in one hour: 3600 ÷ 144 = 25.

If a manager wants one loop to last exactly 3 minutes with 12 slides shown, each slide needs 180 ÷ 12 = 15 seconds.

## Printing the presentation

### Full page slides

Each slide is printed on its own page, filling it, normally in landscape orientation. Use it when every detail of each slide must be checked, for example as evidence of formatting, or when slides are to be pinned up as posters.

### Presenter notes

Presenter notes pages (often called notes pages) show **one slide per page**, as a smaller image at the top, with that slide's **presenter notes underneath**. They are usually portrait. They are printed for the **speaker**, who can hold them while presenting. Only notes typed in the notes pane appear, so check the notes are on the right slides before printing.

### Handouts

Handouts show **several slides on each page** for the **audience** to take away. Common choices are 1, 2, 3, 4, 6 or 9 slides per page. In many packages the three-per-page layout adds ruled lines beside each slide for the audience to write their own notes. You may also be able to choose whether slides run across the page (horizontal order) or down it (vertical order). More slides per page saves paper, but each slide is smaller and harder to read, so 9 per page suits slides with very little text.

### Page count calculations

Number of handout pages = number of slides printed ÷ slides per page, **rounded up**, because a part-filled page still needs a sheet.

| Slides printed | Layout | Calculation | Pages |
|---|---|---|---|
| 16 | 6 per page | 16 ÷ 6 = 2.67, rounded up | 3 |
| 16 | 4 per page | 16 ÷ 4 = 4 | 4 |
| 16 | Presenter notes | 1 slide per page | 16 |
| 16 | Full page slides | 1 slide per page | 16 |

Check whether hidden slides are printed. Many packages have a print option that includes or excludes hidden slides, so read the task: "print all slides" may need hidden slides included.

### Other print settings to check

- **Headers and footers for notes and handouts** are set separately from those on slides. If the task asks for your name on the handouts, add it in the notes and handouts settings.
- **Colour, greyscale or black and white**: greyscale saves ink but check that coloured text is still readable.
- **Which slides**: all, a range such as slides 2 to 5, or the current slide.
- **Print to PDF** if the task asks for an electronic copy of the printout; the PDF must show the layout requested.

## Worked example: choosing and setting outputs

*This brief is invented.* A school has a 10-slide presentation about its library. It will run on a screen in the entrance during open day, with each slide shown for 20 seconds. Later, the librarian will give a talk to parents using the same slides.

1. **Open day**: set each slide's timing to 20 seconds, choose loop continuously until Esc (or kiosk mode) and use timings. One loop takes 10 × 20 = 200 seconds, which is 3 minutes 20 seconds.
2. **Talk to parents**: change the set-up to presenter controlled with manual advance so the timings are ignored. The librarian types reminders in the presenter notes.
3. **Prints**: notes pages for the librarian (10 pages), and handouts for parents at 3 per page so they have lines for notes. 10 ÷ 3 = 3.33, rounded up to 4 pages per parent.

## Common mistakes

- Setting timings but not the loop option, so the carousel stops after the last slide.
- Setting the loop but leaving slides on manual advance, so the carousel never moves.
- Using a carousel for a talk, so slides change while the speaker is talking.
- Printing handouts when presenter notes were asked for, or the other way round.
- Rounding page counts down instead of up.
- Forgetting the name or details the task asks for in the handout header or footer.

## Exam technique

In the practical paper, follow the exact output named, such as "print handouts with 6 slides per page", and check the print preview before printing. In the theory paper, *describe* a looped carousel by saying what it does (runs automatically with timings and repeats), and *explain* a choice with a reason linked to the purpose, for example: "Presenter notes are printed for the speaker because they show each slide with the notes needed to deliver it."
