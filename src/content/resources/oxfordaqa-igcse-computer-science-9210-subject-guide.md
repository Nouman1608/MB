OxfordAQA International GCSE Computer Science (9210) introduces students
to programming, algorithms and the hardware, networks and data that sit
behind everyday computing. It suits anyone who enjoys solving problems
logically and wants a grounding for further study in computing. The
course is linear, with no coursework, and is assessed by two equally
weighted exams of 120 minutes and 80 marks each: an on-screen programming
paper and a written paper on concepts and principles. Exams for this
specification take place in May/June only, with no November series from
2026.

## How the course is organised

The specification has eight topics, which group naturally into three
areas.

**Problem solving and programming.** Topic 1, Algorithms, and topic 2,
Programming, form the practical core. Programming is by far the most
detailed topic, covering data types, programming concepts, arithmetic,
relational and Boolean operations, data structures, input/output and file
handling, string handling, random number generation, subroutines
(procedures and functions), structured programming, robust and secure
programming, and the classification of programming languages and
translators.

**How computers work.** Topic 3, Data representation, and topic 4,
Computer systems, explain how information is stored as binary and how
hardware and software work together.

**Connected and applied computing.** Topic 5, Computer networks; topic 6,
Cyber security; topic 7, Relational databases and structured query
language (SQL); and topic 8, Web page design, apply those ideas to the
systems students use every day.

## How it's assessed

| Paper | Title | Format | Time | Marks | Weighting |
|---|---|---|---|---|---|
| Paper 1 | Programming | On-screen exam based on a pre-released skeleton program, in C#, Python 3 or Visual Basic | 120 minutes | 80 | 50% |
| Paper 2 | Concepts and Principles of Computer Science | Written exam | 120 minutes | 80 | 50% |

Both papers are externally assessed and there is a single, untiered
entry. Because the qualification is linear, both papers are sat in the
same exam series at the end of the course. The pre-released skeleton
program for Paper 1 is something your teacher will work through with you
in the run-up to the exam, so the programming paper rewards students who
have studied it closely as well as those who can code fluently.

## How the parts fit together

The two papers divide the course roughly along the line between doing and
explaining. Paper 1 tests whether you can read, extend and debug real
code under exam conditions, which draws most heavily on topics 1 and 2.
Paper 2 tests whether you can explain how computer systems work, drawing
on topics 3 to 8, though algorithms and programming concepts also appear
there in written form.

Several links are worth noticing early. Data representation underpins
both data types in programming and the way networks transmit data.
Robust and secure programming, part of topic 2, connects directly to the
cyber security content of topic 6. SQL in topic 7 is itself a kind of
programming, so the logical habits you build writing code help when
writing queries. Web page design draws on the same attention to
structure and precision.

The skill that runs through everything is precise reasoning: tracing what
an algorithm does step by step, and explaining it in accurate technical
language.

## Programming as a practical skill

Programming is learned by doing. Reading about loops, subroutines or file
handling helps, but fluency only comes from writing, running and fixing
code regularly. Because Paper 1 is taken on screen, the practical habits
you build during the course, such as testing small sections of code,
reading error messages carefully and using meaningful names, transfer
directly into the exam.

A good routine is to solve one short problem in your chosen language
several times a week, then return to it later and improve it. Make your
programs robust: check what happens with unexpected input, which links to
the robust and secure programming content in topic 2. Practising with
programs written by other people is also valuable, because working with
the pre-released skeleton program means reading and extending code you
did not write yourself.

## Planning your study

Start with algorithms and programming, and keep programming going every
week for the whole course rather than treating it as a block that is
"finished". Choose a language your school supports (C#, Python 3 or
Visual Basic) and use it constantly; short, frequent coding sessions
build fluency far faster than occasional long ones.

Alongside that, work through data representation and computer systems,
then networks and cyber security, and then databases and web page design.
Each later topic builds on the vocabulary of the earlier ones.

In the final months, the focus shifts. Once the skeleton program is
released, study it carefully with your class. Begin past-paper questions
for Paper 2 as soon as each topic has been taught, and move to full
timed papers once you have covered the whole specification. The course's
exam-preparation page covers the skeleton program and Paper 2 technique
in detail, so use that for paper-specific planning.

## Frequently asked questions

**How is OxfordAQA International GCSE Computer Science 9210 assessed?**
By two exams, each 120 minutes long and worth 80 marks and 50% of the qualification: Paper 1, an on-screen programming exam, and Paper 2, Concepts and Principles of Computer Science.

**Is there coursework in 9210?**
No. The qualification is linear and is assessed entirely by the two exams.

**What is the pre-released skeleton program?**
Paper 1 is set against a skeleton program released before the exam, available in C#, Python 3 or Visual Basic. You study it in advance and then answer questions that ask you to work with it on screen.

**Can I sit 9210 in November?**
The board's page states that exams for this specification take place in May/June only, with no November series from 2026.

**Which topic is the largest?**
Topic 2, Programming, has the most detailed content, covering everything from data types and operations to subroutines, robust and secure programming, and translators.
