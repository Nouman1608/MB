Section 8.3 of Cambridge IGCSE ICT 0417 covers threats to data and methods of protecting it. These notes are for recall. The [security of data study guide](/resources/cambridge-igcse-ict-0417-security-of-data/) explains how each threat and protection works, and the [security of data practice questions](/resources/cambridge-igcse-ict-0417-security-of-data-practice/) test you in context.

## Syllabus coverage

| Syllabus wording | Recall |
|---|---|
| Threats to data | Hacking, phishing, pharming, smishing, vishing, viruses, malware, card fraud |
| Card fraud | Shoulder surfing, card cloning, key logging |
| Protection of data | Biometrics, digital certificate, SSL, encryption, firewall, two-factor authentication, user ID and password |

## Threats in one line each

- **Hacking**: unauthorised access to a computer system → data viewed, changed, deleted or stolen.
- **Phishing**: fake **email** → link → fake website → user types details.
- **Pharming**: **malicious code** redirects user to fake website, even if the correct address is typed.
- **Smishing**: phishing by **SMS text**.
- **Vishing**: phishing by **voice call** or voicemail.
- **Virus**: program that **copies itself** into other files → deletes or corrupts data, crashes computer.
- **Malware**: **any** harmful software (viruses are one kind).
- **Shoulder surfing**: **watching** a PIN or password being entered.
- **Card cloning**: **skimmer** copies the card's magnetic stripe data → duplicate card.
- **Key logging**: software or device **records keystrokes** → passwords and card numbers captured.

## Prevention for each threat

| Threat | Help prevent it by |
|---|---|
| Hacking | Firewall; strong passwords; 2FA; account lock-out; encryption; software updates |
| Phishing | Do not click links in unexpected emails; check sender and URL; look for errors and urgency |
| Pharming | Anti-malware; check address bar, https and certificate |
| Smishing | Do not follow links or call numbers in unexpected texts |
| Vishing | Never give details by phone; call back on the official number |
| Viruses and malware | Up-to-date anti-virus; scan downloads; trusted sources only; do not run unknown attachments |
| Shoulder surfing | Shield keypad; be aware of people nearby |
| Card cloning | Check readers for skimmers; use chip or contactless |
| Key logging | Anti-spyware; on-screen keyboard or drop-down selection |

## Protection methods: purpose and how it works

| Method | Purpose | How it works |
|---|---|---|
| Biometrics | Identify the user by a unique characteristic | Fingerprint, face, iris, retina or voice scanned and compared with stored data |
| Digital certificate | Prove a website is genuine | Contains owner's name, serial number, expiry date, public key, certificate authority's digital signature |
| SSL | Secure data in transit | Encrypted link between server and client; https and padlock |
| Encryption | Make data unreadable without the key | Plaintext → ciphertext using a key; used on hard discs, email, cloud, HTTPS websites |
| Firewall | Block unauthorised traffic | Checks traffic in and out against rules; blocks, logs |
| Two-factor authentication | Confirm identity even if password stolen | Two different factors: know, have, are |
| User ID and password | Identify and authenticate the user | ID says who; password proves it; controls access rights |

## Biometrics: for and against

- **For**: cannot be forgotten, lost or lent; hard to copy; quick.
- **Against**: costly equipment; false rejections (cut finger, poor light); privacy; cannot be changed if stolen.

## Strong password checklist

- Mix of upper and lower case, digits, symbols.
- Not a word, name or date linked to you.
- Different for each account.
- Never shared; changed if seen.
- Account locks after repeated failed attempts.

## Key terms

| Term | Meaning |
|---|---|
| Unauthorised access | Using a system without permission |
| Fake website | Copy of a real site made to collect details |
| Skimmer | Device fitted to a card reader to copy card data |
| Spyware | Malware that secretly gathers information, such as a key logger |
| Plaintext | Data before encryption |
| Ciphertext | Encrypted, unreadable data |
| Encryption key | Value used to encrypt and decrypt data |
| Certificate authority | Trusted organisation that issues digital certificates |
| Public key | Key in a certificate used to encrypt data sent to its owner |
| Authentication | Proving a user is who they claim to be |

## Exam traps

- **Phishing = user acts** (clicks a link). **Pharming = user redirected** without doing anything wrong.
- **Smishing and vishing** are phishing by text and by voice: name the channel.
- **Firewalls do not remove viruses.**
- **Encryption does not stop interception**; it makes data unreadable.
- **2FA needs two different types**, not two passwords.
- **Digital certificate: purpose and contents** may both be asked; learn both.
- **Shoulder surfing is not hacking**; it is a card fraud method.

## Self-test

1. Define hacking.
2. State one difference between phishing and pharming.
3. What is smishing?
4. What is vishing?
5. Give two ways to avoid infecting a computer from a downloaded file.
6. Describe card cloning.
7. How can on-screen keyboards protect against key logging?
8. Give two disadvantages of biometrics.
9. State three items found in a digital certificate.
10. How can a user tell that a website is using SSL?
11. Give two places where encryption protects data.
12. Explain how two-factor authentication improves security.

## Self-test answers

1. Gaining unauthorised access to a computer system.
2. Phishing tricks the user into clicking a link in an email; pharming redirects the user to a fake website even when the correct address is typed.
3. Phishing using SMS text messages.
4. Phishing using voice calls or voicemail.
5. Any two of: download only from trusted sources; scan with up-to-date anti-virus before opening; do not run executable attachments from unknown senders; keep software updated.
6. A skimmer copies data from a card's magnetic stripe so that a duplicate card can be made.
7. Characters are selected with the mouse or touch, so no keys are pressed for the logger to record.
8. Any two of: expensive equipment; recognition may fail; privacy concerns; cannot be changed if stolen.
9. Any three of: owner's name; serial number; expiry date; public key; certificate authority's digital signature.
10. The address starts with https and a padlock symbol is shown.
11. Any two of: hard discs; email; cloud storage; HTTPS websites.
12. A second, different type of evidence such as a code sent to the user's phone is needed, so a stolen password alone does not give access.
