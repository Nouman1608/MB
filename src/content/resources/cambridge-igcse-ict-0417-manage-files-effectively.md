Section 11.1 of Cambridge IGCSE ICT 0417, "Manage files effectively", is both a practical skill and theory content. You must be able to "locate stored files", "open and import files of different types", "save files in a planned hierarchical directory/folder structure", "save files using appropriate file names", save and print in a variety of formats, and save and export in application and generic formats. You must also know the "characteristics and uses of file formats including css, csv, gif, htm, jpg, pdf, png, rtf, txt, zip, rar" and "the need for generic file formats".

The [File management study guide](/resources/cambridge-igcse-ict-file-management-study-guide/) introduces naming, extensions and generic formats. This guide goes deeper into each skill the syllabus lists. For quick recall use the [manage files revision notes](/resources/cambridge-igcse-ict-0417-manage-files-effectively-revision-notes/), and test yourself with the [manage files practice questions](/resources/cambridge-igcse-ict-0417-manage-files-effectively-practice/).

## Locating stored files

Every file is stored on a drive (for example the computer's hard disk, a USB flash drive, a network drive or cloud storage) inside a folder. The route from the drive to the file is its **path**, for example *Documents > School > ICT > Task 3*. To locate a file you can:

- browse through the folder structure in the file manager;
- use the file manager's **search** box, searching by name, part of a name, extension or date;
- open the application's **recent files** list;
- sort a folder's contents by name, date modified, type or size to find a file quickly.

Good folder planning makes locating files fast. If every file is saved to the desktop, finding one means scanning a long, unsorted list.

## Saving in a planned hierarchical folder structure

A **hierarchical** structure is a tree: a top-level folder holds subfolders, which hold further subfolders and files. **Planned** means you decide the structure before you start saving, rather than creating folders as files pile up.

### Worked example: planning a structure

A student takes six subjects and produces coursework, notes and past-paper attempts in each. A sensible plan:

- Top level: *School 2026*
- Second level: one folder per subject, such as *ICT*, *Geography*, *Physics*
- Third level inside each subject: *Coursework*, *Notes*, *Practice papers*
- Inside *Coursework*: files named by task and version

The reasoning: the student nearly always knows the subject first, then the type of work, so the folders follow the order in which they think. A file is then never more than three clicks from the top, and similar files sit together for backing up or sending.

## Saving files using appropriate file names

An appropriate name tells the user what the file contains without opening it. For example, *Geog_Rivers_Coursework_v3* is better than *Doc1*. In the practical papers, you are often told exactly what to call a file. Type the name exactly as given, including capital letters, underscores and spaces, because the instruction is the specification of the task.

## Opening and importing files

**Opening** a file loads it into the application that created it, in that application's own format. **Importing** brings data from a file of a different type into the current application. Examples you may meet:

- importing a **.csv** file into a spreadsheet or a database table;
- importing a **.txt** or **.rtf** file into a word-processed document;
- importing a **.jpg** or **.png** image into a document, presentation or web page;
- importing a chart or a spreadsheet extract into a report.

When importing a .csv file into a database, check that each field has been given the correct data type and that the first row has been treated as field names if it contains headings.

## Saving and exporting in different formats

**Save** keeps a file in the application's own (native) format. **Export** (or **Save as** with a different type) writes a copy in another format, often a generic one, for use elsewhere.

### Application package formats named in the syllabus

| Type of software | Formats |
|---|---|
| Word processing | .docx, .doc, .rtf |
| Spreadsheet | .xlsx, .xls, .sdc |
| Database | .accdb, .odb, .sdb |
| Presentation | .pptx, .ppt |

Older formats such as .doc, .xls and .ppt are still used so that files open in older versions of software.

### Generic formats named in the syllabus

.csv, .txt, .rtf, .pdf, .css, .htm, .jpg and .png. Exporting to a generic format may lose features. A spreadsheet exported as .csv keeps the values but loses formulas, formatting, charts and extra worksheets. A document exported as .txt loses all formatting and images. A .pdf keeps the layout exactly but is hard to edit.

## Saving and printing evidence

The syllabus lists the outputs you may need to save or print: a **document**, **screenshots**, **database reports**, **data tables**, **graphs and charts**, a **web page in browser view** and a **web page in HTML view**.

- A **screenshot** captures what is on screen, for example to show a formula, a field's properties or a folder structure. Crop it so the required detail is clear and readable.
- A **web page in browser view** shows how the page appears to a visitor.
- A **web page in HTML view** shows the markup (the code) that produces the page, so the examiner can check the tags and attributes.
- A **database report** is the formatted output of a query; a **data table** shows records in rows and fields in columns.

Before printing, use print preview to check that nothing is cut off, that all required columns fit and that the page orientation suits the content.

## Characteristics and uses of the named file formats

| Format | Characteristics | Typical use |
|---|---|---|
| css | Cascading style sheet: plain text holding style rules for web pages | Giving all pages of a website a consistent appearance |
| csv | Comma-separated values: plain text, one record per line, fields separated by commas | Moving data between spreadsheets and databases |
| gif | Image with up to 256 colours; lossless; supports simple animation and transparency | Simple animations, icons, logos with few colours |
| htm | Hypertext markup: plain text containing tags that a browser displays as a web page | Web pages |
| jpg | Lossy compressed image with millions of colours; small files | Photographs on websites and in documents |
| pdf | Portable document format: fixed layout that looks the same on any device | Sending final documents, forms, manuals |
| png | Lossless compressed image; supports transparency | Logos, diagrams, screenshots |
| rtf | Rich text format: text with basic formatting such as fonts and bold | Moving formatted text between different word processors |
| txt | Plain text with no formatting | Notes, data, program code |
| zip | Compressed archive holding one or more files | Reducing size for storage or email |
| rar | Compressed archive; usually needs separate software to create | Reducing size for storage or transfer |

## The need for generic file formats

A generic format is not tied to one company's software. It is needed because:

- the recipient may use **different software** or a different operating system;
- it allows data to be **moved between applications**, for example from a spreadsheet to a database;
- files remain **readable in the future**, even if the original software is no longer available;
- web formats such as .htm, .css, .jpg and .png work in **any browser**.

## Annotated model answer

*Question: A company exports its sales spreadsheet as a .csv file for a partner firm. Explain one advantage and one disadvantage of this.* **[4]**

> The partner can open a .csv file in almost any spreadsheet or database software (1), so it does not matter that they use different software from the company (1). However, a .csv file only stores the data values (1), so the formulas, formatting and charts in the spreadsheet are lost (1).

*Why it scores:* each side has a point and its consequence in the scenario.

## Common mistakes

- Saying that changing a file's extension by renaming it converts the file. Only exporting or Save as does that.
- Treating import and open as the same: import brings in data of a different type.
- Forgetting that .rtf appears in both lists: it is an application format and a generic one.
- Writing "jpg is lossless". It is lossy; png and gif are lossless.
- Printing a web page only in browser view when HTML view was also asked for.

## Exam technique

**State** a format with its full extension. **Describe** a format by giving two characteristics. **Explain** the need for generic formats with a reason tied to the scenario: different software, moving data or long-term access.
