Section 13.2 of Cambridge IGCSE ICT 0417 asks you to "work with tables within documents". The syllabus breaks this into four skills: "create a table with a specified number of rows and columns"; "place text or objects in a table"; "edit a table and its contents including insert row(s) and column(s), delete row(s) and column(s), merge cells"; and "format a table including to set horizontal cell alignment (left, right, centre, fully justified), set vertical cell alignment (top, middle, bottom), show gridlines, hide gridlines, wrap text within a cell, shading/colouring cells, adjust row height, adjust column width". The [Layout study guide](/resources/cambridge-igcse-ict-layout-study-guide/) introduces tables alongside page layout. This guide works through each named skill and how to follow table instructions exactly.

For quick recall use the [tables revision notes](/resources/cambridge-igcse-ict-0417-tables-revision-notes/), and test yourself with the [tables practice questions](/resources/cambridge-igcse-ict-0417-tables-practice/).

## Creating a table with a specified number of rows and columns

**Rows** run across the table; **columns** run down it. Instructions usually state "columns x rows" or say "3 columns and 7 rows" in words, so read the order carefully.

Count the rows the data needs, including any heading row. A table listing 12 students with a heading row needs **13 rows**. If a title is to sit above the headings inside the table, add one more row and merge it later.

To create the table, use the insert table option and enter the number of columns and rows, rather than drawing it by hand, so the cells are equal and the count is exact.

## Placing text or objects in a table

A cell can hold text, numbers or an object such as an image or a small chart. Type into a cell, or paste into it. Press **Tab** to move to the next cell; pressing Tab in the last cell adds a new row, which is a quick way of adding rows but can also add one by accident.

When placing an image in a cell, resize it to fit the cell, keeping its aspect ratio, so that the row does not stretch to an unexpected height.

## Editing a table

| Edit | How | Note |
|---|---|---|
| Insert row(s) | Select a row, then insert above or below | Selecting two rows first inserts two |
| Insert column(s) | Select a column, then insert left or right | Check the table still fits the margins |
| Delete row(s) or column(s) | Select, then delete rows or columns | Pressing Delete alone clears the **contents**, not the row |
| Merge cells | Select adjacent cells, then merge | Their contents join into one cell |

**Clearing contents** and **deleting a row** are different. If a task says "delete the empty last row", the row itself must go, so use the delete rows command.

**Merging** is used to make one cell span several columns or rows, such as a title across the top of a table or a category label down the side. Merge only the cells named in the instruction; merging too many breaks the table's structure.

## Formatting a table

### Horizontal cell alignment

| Alignment | Effect | Typical use |
|---|---|---|
| Left | Text lines up against the left edge of the cell | Names, descriptions |
| Right | Text lines up against the right edge | Numbers, prices, so units line up |
| Centre | Text sits midway between the left and right edges | Headings, short codes |
| Fully justified | Text spreads so both left and right edges are straight | Long text in a wide cell |

### Vertical cell alignment

| Alignment | Effect |
|---|---|
| Top | Contents sit at the top of the cell |
| Middle | Contents sit halfway between the top and bottom |
| Bottom | Contents sit at the bottom of the cell |

Vertical alignment only shows a difference when the row is taller than its contents, for example after the row height has been increased or when another cell in the row has wrapped onto several lines. Horizontal and vertical alignment are set separately, so "centre the headings horizontally and vertically" needs both settings.

### Showing and hiding gridlines

**Gridlines** are the lines that separate the cells. To **show** them, make all the lines visible so every cell is outlined when printed; in a word processor this is usually done by applying borders to all cells. To **hide** them, remove the lines, so the contents are arranged in rows and columns without visible lines, which is useful when a table is used only to line up a form or a list. Some word processors can show faint on-screen guides for a table without borders; these help with editing but do not print.

### Wrapping text within a cell

When **wrap text** is on, text that is too long for the column width continues on a new line inside the same cell, and the row grows taller. When it is off, text may be hidden or spread past the cell edge. Wrapping keeps a column narrow while still showing all the text.

### Shading or colouring cells

**Shading** fills a cell's background with a colour. It is often applied to the heading row to separate it from the data, or to alternate rows to make long tables easier to read. Choose a light shade so that dark text remains readable, and check the exact colour if the task names one.

### Adjusting row height and column width

Drag the borders for a rough size, but enter values in the table properties when a measurement is given. Row height can usually be set as an **exact** value or **at least** a value, which lets the row grow if the text wraps. Column widths in a table that must fill the text width should add up to that width.

## Worked example: following a table specification

*Instruction:* "Create a table with 4 columns and 7 rows. Merge the cells in the first row and enter the title *Club Fees*. Use the second row for the headings *Activity*, *Day*, *Members* and *Fee*. Centre the headings horizontally and vertically and shade them light grey. Right-align the Fee column. Show all gridlines. The page has a text width of 15 cm: make the first column 6 cm and the other three columns equal."

Working:

1. Insert a table with 4 columns and 7 rows. That gives 1 title row, 1 heading row and 5 data rows.
2. Select the four cells of row 1 and **merge** them; type the title.
3. Type the headings in row 2; set horizontal alignment to **centre** and vertical alignment to **middle**; apply light grey **shading**.
4. Select the data cells in the Fee column and set **right** alignment.
5. Apply borders to all cells so all **gridlines show**.
6. Column widths: 15 - 6 = 9 cm remaining; 9 / 3 = **3 cm** each. Check: 6 + 3 + 3 + 3 = 15 cm.

## Common mistakes

- Swapping rows and columns when creating the table.
- Forgetting to count the heading row, so the table is one row short.
- Pressing Delete to "delete" a row, which only clears the text.
- Setting horizontal centre but forgetting vertical middle when both are asked for.
- Leaving gridlines visible when the task says hide them, or hiding them when it says show them.
- Dragging column borders when exact widths were given.
- Merging cells beyond those named, which removes cells the data needs.

## Exam technique

Break the table instruction into its parts (size, content, edits, horizontal and vertical alignment, gridlines, wrapping, shading, heights and widths) and check each after finishing. In theory questions, **describe** a formatting choice by saying what it does and **explain** why it suits the data: "right-align the prices **so that** the digits line up and can be compared".

## Check your understanding

1. A table lists 20 products with a heading row. How many rows does it need? *21.*
2. What is the difference between clearing a row and deleting it? *Clearing removes the contents; deleting removes the row.*
3. When does vertical alignment make a visible difference? *When the row is taller than its contents.*
4. Why might a designer hide gridlines? *When the table is only used to line up a form or list, so no lines are wanted.*
