These questions cover **section 16.8 Methods of software development** of the Cambridge International AS & A Level Information Technology 9626 syllabus for examination in 2025, 2026 and 2027 (version 4). This is **A Level only** content examined in Paper 3 (Advanced Theory), where calculators are not allowed. All questions can be answered on paper.

## Questions

**1.** State the **five** methods of software development named in the syllabus. **[5]**

**2.** Describe how the waterfall method works. **[3]**

**3.** Give **two** advantages and **two** disadvantages of the waterfall method. **[4]**

**4.** Explain the difference between iterative development and incremental development. **[3]**

**5.** A software company is building a booking system for a chain of 20 gyms. The system will have separate modules for class bookings, membership payments and equipment maintenance. The class booking module is needed first.

**(a)** Explain why incremental development is suitable. **[2]**
**(b)** Describe how the system would be developed using this method. **[3]**
**(c)** Give **one** disadvantage of using this method here. **[1]**

**6.** A start-up is building a mobile app to help runners find routes. The founders are not sure which features users will want and expect to change their plans often. They can meet the developers every week.

**(a)** Describe how agile development would work for this project. **[3]**
**(b)** Explain why waterfall would be unsuitable. **[2]**
**(c)** Give **one** disadvantage of agile for this project. **[1]**

**7.** Describe the main features of rapid application development (RAD). **[3]**

**8.** A college needs an internal tool for room bookings within six weeks. Several teachers are willing to help design it.

Evaluate the use of RAD for this project. **[4]**

**9.** A company is developing the control software for a hospital's infusion pump. The rules are laid down by law and cannot change. Any fault could harm a patient.

Evaluate waterfall and agile for this project, and recommend a method. **[6]**

## Answers

**1.** Agile [1]; iterative [1]; incremental [1]; rapid application development (RAD) [1]; waterfall. [1] **[5]**

**2.** The stages (requirements or analysis, design, build, test, implementation, maintenance) are carried out one after another in a fixed order [1]; each stage is completed and signed off before the next one begins [1]; there is little or no going back to an earlier stage. [1] **[3]**

**3.** Advantages (any two): simple to understand and manage; clear milestones and documents; easy to plan cost and time; suits clear, fixed requirements. [1 each]
Disadvantages (any two): hard to change requirements once a stage is complete; users see the system only at the end; early mistakes are found late and cost more to fix; slow to deliver any benefit. [1 each] **[4]**

**4.** Iterative development builds a rough version of the whole system and then repeats the cycle to refine and improve it [1]; incremental development splits the system into parts and builds and delivers each part in turn, adding it to the earlier ones [1]; so iterative refines the whole, while incremental adds finished parts. [1] **[3]**

**5. (a)** The system divides into independent modules [1], and the class booking module is needed first, so it can be delivered and used early. [1] **[2]**
**(b)** Build, test and deliver the class booking module first [1]; then build and deliver the membership payments module and then the equipment maintenance module in turn [1]; each is added to the system and tested together with the earlier ones. [1] **[3]**
**(c)** Any one: the modules must be designed to fit together, which needs overall planning at the start; integration work is needed; the complete system takes longer. [1] **[1]**

**6. (a)** Work is done in short sprints of one to four weeks [1]; at the start of each sprint the team and founders choose features from a prioritised list, and the team delivers working software at the end [1]; the founders give feedback at the weekly meetings and can change the priorities for the next sprint. [1] **[3]**
**(b)** In waterfall the requirements and design are fixed before building starts [1], so it is hard to change when the founders change their plans, and users would see nothing until the end. [1] **[2]**
**(c)** Any one: the final cost, time and feature list are hard to predict; needs constant involvement from the founders; less documentation. [1] **[1]**

**7.** Any three: quick prototypes are built and refined [1]; users take a strong part in the design, for example in workshops [1]; reusable components and development tools are used to speed up construction [1]; work is time-boxed with fixed short deadlines [1]. **[3]**

**8.** Suitable (up to 2 marks): fast delivery fits the six-week limit [1]; the teachers' involvement fits RAD's use of user workshops and prototypes, so the tool will suit their needs. [1]
Less suitable (up to 1 mark): the teachers have to be available, which takes time from teaching; quality and documentation may suffer. [1]
Judgement (1 mark): for example RAD is a good fit because the tool is small, internal and not critical. [1]
Maximum 4. **[4]**

**9.** Waterfall (up to 2 marks): suits fixed requirements and gives full documentation and sign-off of each stage, which helps in checking safety [1]; but changes are hard, and users see the system only at the end, so mismatches show late. [1]
Agile (up to 2 marks): fast, flexible, with frequent feedback [1]; but less documentation, and the cost and final features are harder to predict, which is a problem for a safety-critical, regulated device. [1]
Link to the scenario (1 mark): the rules are fixed by law, so the flexibility of agile is not needed, and a fault could harm patients, so thorough documentation and checking at each stage are essential. [1]
Recommendation (1 mark): waterfall, justified. [1]
Maximum 6. **[6]**
*Examiner insight:* "Evaluate" needs a clear recommendation based on the scenario. An answer that lists points about both methods and stops will not reach full marks.

## Where marks are usually lost

- Confusing iterative with incremental.
- Giving "it is quick" as a reason for several different methods.
- Not linking the choice to the scenario (modules, uncertain requirements, safety).
- Leaving out the weakness of the chosen method.
- Stating agile has "no documentation" instead of less.

## Frequently asked questions

**How do I pick a development method in an exam?**
Read the scenario for clues: fixed or changing requirements, modules, speed, user availability and safety. Match these to the method and justify it.

**Do I need to know all five methods?**
Yes. The syllabus names agile, iterative, incremental, RAD and waterfall, with their stages and processes and their advantages and disadvantages.
