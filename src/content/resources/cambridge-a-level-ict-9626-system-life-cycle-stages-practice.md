These questions cover **section 16.1 The stages in the system life cycle** of the Cambridge International AS & A Level Information Technology 9626 syllabus for examination in 2025, 2026 and 2027 (version 4). This is **A Level only** content examined in Paper 3 (Advanced Theory), where calculators are not allowed. All questions can be answered on paper.

## Questions

**1.** Define the term *system*. **[2]**

**2.** State whether each of the following is a hardware system, a software system or a combination of hardware and software.

**(a)** A traffic-light controller made up of lamps, a timer unit, road sensors and the program that changes the lights. **[1]**
**(b)** A stock-control package running on a company's existing computers. **[1]**
**(c)** A set of network cables, switches and routers joining the rooms of a school. **[1]**

**3.** The stages of developing a system are shown below in the wrong order:

implementation, analysis, evaluation, design, documentation, development and testing

Write the stages in the correct order. **[3]**

**4.** State the stage of the system life cycle in which each of the following takes place.

**(a)** The analyst interviews the managers of a clinic about their problems with the current appointment system. **[1]**
**(b)** The team draws a data flow diagram and designs the input forms. **[1]**
**(c)** The developers write the program and run tests on each module. **[1]**
**(d)** The clinic's receptionists are given a booklet explaining how to book a patient. **[1]**

**5.** Explain why the output of one stage is important to the stage that follows it. Use two different pairs of stages in your answer. **[4]**

**6.** A clinic's new appointment system has been written. During testing, the testers find that there is no field on the input form for a patient's mobile number, which the user requirements specification says is needed.

**(a)** Name the stage the team should return to, and justify your choice. **[2]**
**(b)** Describe what must be done before the system is tested again. **[2]**

**7.** Six months after a retail company introduced a new online ordering system, an evaluation shows that customers want to pay by a new method that did not exist when the system was designed.

Explain how this shows that the stages form a cycle and not a straight line. **[3]**

**8.** A manager says: "Documentation can wait until the system has been running for a year." Discuss this view. **[4]**

## Answers

**1.** A collection of components [1] that work together to form a whole. [1] **[2]**
*Examiner insight:* "A computer" or "a program" is not a definition; the answer needs the idea of components forming a whole.

**2. (a)** A combination of hardware and software. [1] **[1]**
**(b)** A software system. [1] **[1]**
**(c)** A hardware system. [1] **[1]**
*Examiner insight:* The words "existing computers" in (b) matter: the system being developed is the software.

**3.** Analysis, design, development and testing, implementation, documentation, evaluation.
Award 3 marks for all six in the correct order, 2 marks for one adjacent pair swapped, 1 mark for analysis first and evaluation last with the middle incorrect. Accept documentation before implementation. **[3]**
*Examiner insight:* In real projects documentation is written throughout, so either order of implementation and documentation is accepted; do not move analysis, design or evaluation.

**4. (a)** Analysis. [1] **[1]**
**(b)** Design. [1] **[1]**
**(c)** Development and testing. [1] **[1]**
**(d)** Documentation (user documentation). [1] **[1]**

**5.** Two pairs, each with a stage output and its use (2 marks each):
- The specifications from analysis [1] tell the designers what the system must do, so the design can be checked against them. [1]
- The design from the design stage [1] tells developers what to build, so they build forms and files to a plan. [1]
- The tested system [1] is what is implemented, so users receive a system that has been checked. [1]
- The specifications from analysis [1] are what evaluation compares the live system with. [1]
Accept any two valid pairs. **[4]**
*Examiner insight:* Name the output, such as the specification or design, then say what the next stage does with it.

**6. (a)** Design [1], because the mobile number field is missing from the form design, so the fault is in the design and not just in the code. (Accept analysis or design with a valid justification; do not accept implementation.) [1] **[2]**
**(b)** Add the field to the design of the input form and the data storage, and update the design documents [1]; then change the program and database to match and retest the new field and the parts that use it. [1] **[2]**

**7.** Evaluation found a new need [1]. This is fed back to analysis, where a new user requirement is written [1], and the later stages (design, development and testing, implementation) are repeated for the change, so the process goes round again. [1] **[3]**

**8.** For (up to 1 mark): there is no urgency if the system is not yet changing, and writing it later may save effort.
Against (up to 3 marks):
- Documentation is needed from analysis and design onward to record the requirements and design, which developers and testers use. [1]
- Users need user documentation when the system is implemented, or they cannot use it properly, and the help desk will be overloaded. [1]
- Technical documentation is needed for maintenance; details are forgotten, or staff leave, if it waits a year. [1]
- Conclusion: the view is not sound; documentation should be produced during the project. [1]
Maximum 4. **[4]**
*Examiner insight:* "Discuss" needs both sides and a conclusion. A one-sided answer is capped.

## Where marks are usually lost

- Defining a system as a computer or as a program.
- Writing analysis and design as if they mean the same thing: analysis finds what is needed, design plans how.
- Naming a stage without justifying it.
- Saying only "so it can be checked" without naming what is checked.
- Forgetting that evaluation can lead back to analysis.

## Frequently asked questions

**Is the system life cycle on the Paper 3 syllabus?**
Yes. The system life cycle is topic 16 of Cambridge International AS & A Level Information Technology (9626) and is A Level only. It is examined in Paper 3 Advanced Theory.

**Which stage comes first in the system life cycle?**
Analysis comes first. Without it, designers and developers do not know what the users need.
