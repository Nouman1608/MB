These notes condense subtopic 6.2 of Cambridge IGCSE ICT 0417, modelling applications. For explanations and a worked what-if calculation, use the [modelling applications study guide](/resources/cambridge-igcse-ict-0417-modelling-applications/); to test yourself, use the [modelling applications practice questions](/resources/cambridge-igcse-ict-0417-modelling-applications-practice/).

## Syllabus coverage

- Computer modelling including personal finance, bridge and building design, flood water management, traffic management and weather forecasting.
- Advantages and disadvantages of using computer modelling rather than humans.

## Key terms

| Term | Meaning |
|---|---|
| Computer model | A representation of a real system using data, formulas and rules, run on a computer |
| Variable | An input value that can be changed to test its effect |
| Rule or formula | A relationship that calculates outputs from inputs |
| What-if analysis | Changing one or more inputs to see the effect on the outputs |
| Simulation | Running a model over time to see how a situation develops |
| Prototype | A real, physical trial version of a product, which a model can replace |
| Output | The prediction or result the model produces |

## The five applications in one table

| Application | Typical inputs | Typical outputs | Main reason to model |
|---|---|---|---|
| Personal finance | Income, bills, spending, interest rate | Money left, savings over time, loan cost | Test a decision before committing |
| Bridge and building design | Shape, materials, loads, wind, earthquakes | Stress points, whether it bends or fails | Cannot test a real structure to destruction |
| Flood water management | Rainfall, river level, land height, ground wetness, defences | Areas flooded, depth, timing | Plan barriers, warnings and evacuation without a real flood |
| Traffic management | Vehicles per minute, light timings, layout, lanes | Queue lengths, journey times | Try changes before paying for roadworks |
| Weather forecasting | Temperature, pressure, humidity, wind, rainfall from stations, satellites, balloons, buoys | Forecast maps, chance of rain | Data too large for people; cannot experiment on the atmosphere |

## Using a model: the steps

1. Collect data and identify the variables.
2. Write the rules and formulas that link them.
3. Test the model against known past results.
4. Change inputs to ask what-if questions.
5. Study the outputs and make a decision, using human judgement.

## Modelling rather than humans

### Advantages

- Cheaper than building prototypes or real test structures.
- Safer: floods, collapses and crashes can be tested with no risk to people.
- Faster: many scenarios run in minutes; time can be speeded up.
- Variables easy to change; the model can be rerun many times.
- Handles very large amounts of data and complex calculations.
- Fewer arithmetic errors than calculation by hand.

### Disadvantages

- Accuracy depends on the input data and the rules ("garbage in, garbage out").
- Real life is more complex; the model may leave out factors.
- Software, hardware and expertise are expensive.
- People may trust results too much.
- Results still need interpreting by experts.

## Match the advantage to the scenario

Examiners reward the advantage that fits the application best:

| Scenario | Strongest advantage to give |
|---|---|
| Testing a skyscraper against earthquakes | Safety: no real building has to fail, so no one is put at risk |
| Comparing ten possible junction layouts | Cost and speed: only the best layout is built |
| Planning savings over 20 years | Time can be speeded up; years of results appear at once |
| Producing tomorrow's forecast | Huge data volumes processed far faster than people could manage |
| Choosing where to put a flood barrier | Many rainfall levels can be tested without waiting for a flood |

## Quick calculation practice

Figures invented. A weekly budget has income £400 and outgoings of £120, £90 and £60.

- Outgoings: 120 + 90 + 60 = £270.
- Money left: 400 − 270 = £130 a week.
- What if the £90 item rises by a third? A third of 90 is 30, so it becomes £120; outgoings £300; money left £100.

## Exam traps

- Writing "a model shows exactly what will happen". It predicts.
- Saying "cheaper" or "safer" without comparing with the real alternative.
- Confusing modelling (6.2) with control (6.3): a model predicts; a control system acts on the real world.
- Forgetting that weather forecasting uses real data from sensors and satellites as input.
- Writing advantages only, when the question asks for disadvantages too.

## Self-test

1. Define a computer model.
2. What is a what-if question?
3. Name the five modelling applications in the syllabus.
4. Give two inputs to a flood water model.
5. Give one output of a traffic management model.
6. Why are bridges modelled before they are built?
7. Name two sources of input data for weather forecasting.
8. Give two advantages of modelling over testing in real life.
9. Give two disadvantages of computer modelling.
10. A budget has income £950 and outgoings £720. How much is left?
11. In question 10, outgoings rise by £80. What is left now?
12. State one way modelling differs from a computer controlled system.

### Answers

1. A representation of a real system using data, formulas and rules, run on a computer to make predictions.
2. Changing an input to see how the outputs change.
3. Personal finance; bridge and building design; flood water management; traffic management; weather forecasting.
4. Any two: rainfall; river level or flow; height of the land; how wet the ground is; position of defences.
5. Queue lengths or journey times.
6. So loads, wind and earthquakes can be tested until the design is safe, without the cost and danger of a real failure.
7. Any two: weather stations; satellites; weather balloons; ocean buoys.
8. Any two: cheaper; safer; faster; easy to change variables and rerun.
9. Any two: only as accurate as its data and rules; simplifies reality; expensive to set up; people may trust it too much.
10. £950 − £720 = £230.
11. Outgoings £800, so £150 is left.
12. A model predicts what might happen; a control system uses sensors and actuators to act on the real world.
