Section 7.4 of Cambridge IGCSE ICT 0417 covers the four methods of changing from an old system to a new one. You need the characteristics, uses, advantages and disadvantages of each. These notes are for recall; the [implementation study guide](/resources/cambridge-igcse-ict-0417-implementation/) works through choosing a method for a scenario, and the [implementation practice questions](/resources/cambridge-igcse-ict-0417-implementation-practice/) test it.

## Syllabus coverage

| Syllabus wording | Recall |
|---|---|
| System implementation: four methods | Direct changeover, parallel running, pilot running, phased implementation |
| For each | Characteristics, uses, advantages, disadvantages |

## The four methods on one page

| Method | What happens | Use when | Main advantage | Main disadvantage |
|---|---|---|---|---|
| Direct changeover | Old system stops; new one starts the same day | Small organisation; low risk; old system cannot continue | Cheapest and quickest; benefits at once | No fall-back if the new system fails |
| Parallel running | Both systems run together; outputs compared | Failure would be serious (money, health, legal) | Old system is a fall-back; errors found by comparison | Most expensive: work done twice |
| Pilot running | Whole new system in one branch first, then the rest | Several similar branches or departments | Failure affects only one site | Other sites wait; pilot site may not be typical |
| Phased implementation | One part of the system at a time, across the organisation | System splits into clear modules | Failure affects only one part | Slow; old and new parts must share data |

## Extra points for each method

**Direct changeover**
- All staff must be trained before the changeover date.
- Data must be fully transferred before the switch.
- Highest risk of the four methods.

**Parallel running**
- Staff workload doubles; overtime or temporary staff may be needed.
- Staff can learn the new system while the old one still works.
- The old system is stopped only when the new one has proved reliable.

**Pilot running**
- Staff at the pilot site become experienced and can train others.
- Faults found at the pilot site are fixed before roll-out.
- Cheaper than parallel running everywhere.

**Phased implementation**
- Each part is checked before the next is introduced.
- Problems are easy to trace to the part just introduced.
- Only possible if the system can be divided into parts.

## Pilot versus phased

| | Pilot | Phased |
|---|---|---|
| How much of the system first? | All of it | One part |
| Where first? | One site | Everywhere |
| Example | Full new library system in one branch library | Book loans module in all branches, then reservations module |

## Choosing a method: quick guide

- **Lives, money or legal records at risk** → parallel running (or a pilot with parallel running at the pilot site).
- **Small, single site, low risk, low budget** → direct changeover.
- **Many similar branches** → pilot running.
- **Clear modules** → phased implementation.

Always justify with a fact from the scenario and, for top marks, say why another method is less suitable.

## Ranking the methods

| Factor | Lowest | Highest |
|---|---|---|
| Cost | Direct | Parallel |
| Risk of losing data or service | Parallel | Direct |
| Time to complete | Direct | Phased (and pilot across many sites) |

## Key terms

| Term | Meaning |
|---|---|
| Implementation | Changing over from the old system to the new one |
| Direct changeover | Replacing the old system with the new one immediately |
| Parallel running | Running old and new systems together for a time |
| Pilot running | Introducing the whole system at one site first |
| Phased implementation | Introducing the system one part at a time |
| Fall-back | A working system that can be used if the new one fails |
| Roll-out | Introducing the system to the remaining sites after a pilot |

## Exam traps

- **Pilot = whole system, one place. Phased = one part, everywhere.** Swapping these is the most common error.
- **"Safer"** needs a reason: the old system is still available.
- **"Cheaper"** needs a reason: work is not duplicated.
- **Do not recommend parallel running automatically.** Weigh its cost against the risk in the scenario.
- **A one-site organisation cannot pilot** in the usual sense: there is no other site to roll out to.
- **Implementation is not testing.** Testing comes first, in development and testing.

## Self-test

1. Name the four methods of implementation.
2. Which method has no fall-back if the new system fails?
3. Give one disadvantage of parallel running.
4. Describe pilot running.
5. Describe phased implementation.
6. Which method is the cheapest? Give a reason.
7. Why is parallel running suitable for a payroll system?
8. A chain of 12 cinemas is installing a new booking system. Which method would you suggest and why?
9. A school's new system has separate modules for attendance, reports and fees. Which method suits it?
10. Give one advantage of phased implementation.
11. Why might a pilot site not show every problem?
12. Give two things that must be in place before a direct changeover.

## Self-test answers

1. Direct changeover, parallel running, pilot running, phased implementation.
2. Direct changeover.
3. Any one of: expensive; work done twice; heavy staff workload; benefits delayed.
4. The whole new system is introduced at one site or department first, then at the others.
5. The new system is introduced one part at a time across the organisation.
6. Direct changeover, because work is not duplicated and it is completed at once.
7. Payroll errors would affect staff pay, so the old system is kept as a fall-back and outputs can be compared.
8. Pilot running, because the cinemas are similar, so one can test the system and limit failure to one site.
9. Phased implementation, one module at a time.
10. Any one of: failure affects only one part; staff learn gradually; each part checked before the next.
11. It may not be typical: it might be smaller, quieter or have more experienced staff than other sites.
12. Trained staff and fully transferred data.
