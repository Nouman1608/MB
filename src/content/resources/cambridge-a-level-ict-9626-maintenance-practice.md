## Questions

**1.** State the **four** types of maintenance. **[4]**

**2.** Identify the type of maintenance in each of the following cases.

**(a)** A library system shows the wrong fine when a book is returned on a bank holiday, and the code is corrected. **[1]**
**(b)** A hospital system is changed because the government has introduced a new rule on how patient data must be stored. **[1]**
**(c)** Nurses ask for a button that prints a patient's wristband, and one is added. **[1]**
**(d)** The support team replaces an old, unsupported database component with a current one before it causes any problem. **[1]**

**3.** Describe what is meant by corrective maintenance, and explain why it is needed even when a system has been thoroughly tested. **[3]**

**4.** An online shop's website stops working properly after a payment company changes the way it receives card details.

**(a)** Name the type of maintenance needed and explain why. **[2]**
**(b)** Describe how this maintenance would be carried out. **[4]**

**5.** Explain the difference between perfective and preventive maintenance, using an example of each. **[4]**

**6.** Give **two** reasons why every maintenance change must be followed by updating the documentation. **[2]**

**7.** A company's payroll system has run for seven years. The original developers have left and the technical documentation is incomplete. The IT manager proposes a six-month programme of preventive maintenance.

Evaluate this proposal. **[6]**

## Answers

**1.** Corrective [1]; adaptive [1]; perfective [1]; preventive. [1] **[4]**

**2. (a)** Corrective. [1]
**(b)** Adaptive. [1]
**(c)** Perfective. [1]
**(d)** Preventive. [1] **[4]**

**3.** Corrective maintenance is fixing faults (bugs) that are found once the system is in use [1]. It is needed because testing can show that faults exist but cannot prove that none remain [1]; real users use the system in ways, and with data, that the tests did not cover. [1] **[3]**

**4. (a)** Adaptive maintenance [1], because the system worked but the environment (the payment company's method) has changed, so the website must be changed to keep working. [1] **[2]**
**(b)** Identify exactly what has changed in the payment company's requirements and which parts of the site are affected [1]; modify the code or settings that send card details [1]; test the changes, including some real or test payments, in the new environment [1]; release the change and update the documentation. [1] **[4]**

**5.** Perfective maintenance improves a system that is working, to add features or make it faster or easier to use, at the request of users [1]; example: speeding up a slow search. [1] Preventive maintenance changes the system to avoid problems in the future, before any fault occurs [1]; example: tidying unclear code and updating its documentation. [1] **[4]**
*Examiner insight:* Both types are planned and no fault has occurred. The difference is the aim: add value (perfective) or remove a future risk (preventive).

**6.** Any two: so that future maintainers know how the system now works and are not misled [1]; so that users and support staff have correct instructions [1]; so that the next change can be planned and tested against an accurate description [1]. **[2]**

**7.** Advantages (up to 3 marks):
- Clearer code and updated documentation make later changes quicker and cheaper, which matters because the developers have left. [1]
- Weaknesses such as old components or poor security can be removed before they cause failures or data loss. [1]
- Work can be planned for quiet periods in the payroll calendar so there is little disruption. [1]
Disadvantages (up to 3 marks):
- It costs six months of staff time and money now, and users will see no change. [1]
- Changes to a system with poor documentation could introduce new faults, so thorough testing is needed. [1]
- The money might have been better spent on adaptive or perfective work that is needed sooner. [1]
Conclusion (1 mark): a justified judgement, for example it is worthwhile for a payroll system, because errors in pay would be serious, as long as the work is phased and tested and the documentation is rewritten first. [1]
Maximum 6. **[6]**
*Examiner insight:* A judgement must use the scenario (seven years old, developers gone, payroll) and not just general points about preventive maintenance.

## Where marks are usually lost

- Calling a change for a new law "perfective" instead of adaptive.
- Calling the improvement of working software "preventive".
- Saying that preventive maintenance fixes a fault.
- Describing how maintenance is carried out without testing.
- Not mentioning the documentation.
- Giving advantages only.

## Frequently asked questions

**How do I identify the type of maintenance in a scenario?**
Ask what caused the change. A fault is corrective, a change in the environment is adaptive, a user wish for improvement is perfective and removing a risk before it causes trouble is preventive.

**What should I include when asked how maintenance is carried out?**
Identify the need, find the part affected, make the change, test it, release it and update the documentation.
