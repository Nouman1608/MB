## Why reduce file size?

**Storage**

- Devices and cloud accounts have fixed capacity.
- More files fit, so extra storage is needed later or not at all.
- Back-ups are quicker and smaller.
- Rarely used files can be archived to free space.

**Transmission**

- Email attachment limits reject large files.
- Smaller files upload and download faster.
- Less bandwidth and data allowance used.
- Web pages load faster.
- One archive replaces many attachments and keeps the folder structure.

## .zip and .rar

| | .zip | .rar |
|---|---|---|
| Type | Compressed archive | Compressed archive |
| Compression | Lossless | Lossless |
| Support | Built into most operating systems | Usually needs separate software to create |
| Extra features | Password protection | Password protection; splitting into parts of a set size |

**Lossless** means extracted files are identical to the originals, so archives suit documents, spreadsheets, databases and programs.

## How compression behaves

- Text, spreadsheets and databases contain repeated patterns, so they **shrink a lot**.
- .jpg, .mp3 and .mp4 files are **already compressed**, so archiving them saves little.
- Very small files give a tiny saving: compression is not "necessary".

## Choosing the right action

| Situation | Best action |
|---|---|
| Many documents to email | One .zip archive |
| Archive still over the attachment limit | Split into parts (.rar) or send a cloud link |
| Recipient may not have archive software | Use .zip, which most systems open |
| Confidential files to send | Archive with a password, and send the password separately |
| Old projects filling a drive | Archive them, then delete the uncompressed copies once checked |

## Steps to remember

**Compress:** select files, choose compress or add to archive, name the archive, choose location, set a password if needed, check the new size.

**Extract:** locate the archive, choose extract, choose the destination folder, open the extracted files.

## Formulae

| Quantity | Formula |
|---|---|
| Compression ratio | original size / compressed size |
| Saving | original size - compressed size |
| Percentage reduction | saving / original size x 100 |
| Size in megabits | size in megabytes x 8 |
| Transmission time (s) | size in megabits / speed in Mbit/s |

**Quick example:** 30 MB compresses to 10 MB. Ratio 3 to 1; saving 20 MB; reduction 66.7%. At 8 Mbit/s: original 240 megabits takes 30 s; compressed 80 megabits takes 10 s.

## Key terms

| Term | Meaning |
|---|---|
| File compression | Reducing the size of a file by encoding its data more efficiently |
| Archive | A single file holding one or more compressed files and folders |
| Extract | Restore the original files from an archive |
| Lossless | Compression in which no data is lost |
| Attachment limit | The largest file an email system will send |
| Bandwidth | The amount of data a connection can carry in a given time |
| Compression ratio | How many times smaller the compressed file is |

## Exam traps

- .zip and .rar are **lossless**: never say they reduce quality.
- Compressing a .jpg gives **little** saving.
- Compressed size can **still** exceed an attachment limit: calculate and compare.
- B means bytes, b means bits: **multiply MB by 8** for megabits.
- The recipient must **extract** an archive before working on the files.
- Give a **transmission** reason when the question is about sending, and a **storage** reason when it is about saving.

## Self-test

1. Give two reasons for reducing file sizes for storage.
2. Give two reasons for reducing file sizes for transmission.
3. What type of compression do .zip and .rar use?
4. Why is lossless compression necessary for a spreadsheet?
5. State one feature of .rar not usually offered by built-in .zip tools.
6. Why does compressing a folder of .jpg photos save little space?
7. A 72 MB folder compresses to 18 MB. Calculate the compression ratio.
8. Calculate the percentage reduction for question 7.
9. How long does the 18 MB archive take to send at 24 Mbit/s?
10. A file compresses to 32 MB but the attachment limit is 20 MB. Suggest two solutions.
11. List the steps to extract an archive.
12. Give one situation where compressing a file is not necessary.

## Self-test answers

1. Any two: fixed device or cloud capacity; more files fit; quicker, smaller back-ups; archiving rarely used files frees space.
2. Any two: attachment limits; faster upload and download; less bandwidth or data used; one file instead of many.
3. Lossless.
4. Every value and formula must be restored exactly; any lost data would cause errors.
5. Splitting the archive into several parts of a chosen size.
6. They are already compressed, so little repetition remains.
7. 72 / 18 = 4 to 1.
8. Saving 54 MB; 54 / 72 x 100 = 75%.
9. 18 x 8 = 144 megabits; 144 / 24 = 6 seconds.
10. Split the archive into parts under 20 MB, or upload to cloud storage and send a link.
11. Locate the archive, choose extract, choose the destination, open the files.
12. A very small file, where the saving would be tiny (or files already in a compressed format).
