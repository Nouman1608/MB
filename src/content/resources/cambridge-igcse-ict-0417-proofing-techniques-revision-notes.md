These notes cover section 15.2 Proofing techniques of Cambridge IGCSE ICT 0417: visual verification of data entry, proofreading a document, and the methods and purpose of verification. The full explanation, with worked examples, is in the [proofing techniques study guide](/resources/cambridge-igcse-ict-0417-proofing-techniques/). ## Syllabus coverage

| Syllabus statement | Notes and guidance (summarised) |
|---|---|
| Perform visual verification | Find and correct transposed numbers, incorrect spelling, inconsistent character spacing, inconsistent case |
| Proofread | Correct inconsistent line spacing; remove blank pages/slides; remove widows/orphans; correct inconsistent or incorrect styles; keep tables and lists from being split over columns or pages/slides |
| Verification | Importance, characteristics and uses of visual checking and double data entry; the need for validation as well as verification |

## Key terms

| Term | Meaning |
|---|---|
| Verification | Checking that data has been copied accurately from its source |
| Visual checking | A person compares the entered data with the source document |
| Double data entry | Data is entered twice and the computer compares the two versions, reporting differences |
| Transposed numbers | Two digits typed in the wrong order, such as 61 for 16 |
| Orphan | First line of a paragraph alone at the bottom of a page or column |
| Widow | Last line of a paragraph alone at the top of a page or column |
| Formatting marks | Hidden symbols shown on screen for spaces, paragraph marks, tabs and breaks |
| Proofreading | Reading the finished document carefully to find errors of content, language and layout |

## Visual verification: four errors

| Error | Example (source then typed) | How to spot it |
|---|---|---|
| Transposed numbers | 2063 then 2036 | Read numbers digit by digit against the source |
| Incorrect spelling | Kowalczyk then Kowalcyk | Compare letter by letter; a spell checker will not help with names |
| Inconsistent character spacing | one space then two spaces between words | Show formatting marks |
| Inconsistent case | Main Street then main street | Compare capitals; look at the same field in other records |

## Proofreading checklist

- **Line spacing**: same in every body paragraph; fix by applying one style.
- **Blank pages or slides**: remove empty paragraphs, stray page breaks and unused slides.
- **Widows and orphans**: use widow/orphan control or keep lines together, not blank lines.
- **Styles**: every heading and paragraph has the correct style; no hand-formatted copies.
- **Split tables and lists**: keep rows together, add a break before the table, or resize to fit; a list must not break across columns, pages or slides.
- Check in **print preview**, because breaks and blank pages show there clearly.

## Verification methods compared

| | Visual checking | Double data entry |
|---|---|---|
| Who compares | A person | The computer |
| Speed and cost | Quick, cheap | About twice the entry time |
| Best for | Small amounts of data; reading back to a customer | Large volumes of important data; "confirm password" boxes |
| Misses | Errors the checker overlooks | The same error made in both entries; errors on the source |

## Why both validation and verification

- **Validation** (15.1) rejects data that breaks rules, such as an age of 250 or a blank field.
- **Verification** finds copying errors that obey the rules, such as 2063 typed as 2036.
- Each misses what the other catches, so use both.
- **Neither** can fix an error that is already on the source document.

## Exam traps

- Verification does **not** check data is sensible; it checks the copy matches the original.
- In double data entry say the **computer compares** the two copies; "typing it twice" alone is incomplete.
- Do not reverse **widow** and **orphan**.
- "Read it again" is not a description of visual checking: mention comparing with the **source document**.
- A spell checker cannot verify **names**, **numbers** or **case**.
- Remember **slides** as well as pages: blank slides and tables split across slides are named in the syllabus.

## Self-test

1. Define verification.
2. Name the two verification methods in the syllabus.
3. In double data entry, what happens when the two entries differ?
4. Give one use of double data entry seen on websites.
5. The source shows 1849 and the screen shows 1489. Name the error.
6. Give one weakness of visual checking.
7. Give one weakness of double data entry.
8. What is an orphan?
9. How should a widow be removed?
10. A table's header row is at the bottom of page 3 and its data is on page 4. Give one way to fix it.
11. Give an example of an error that validation would catch but that verification might miss.
12. Why are both validation and verification needed?

### Answers

1. Checking that data has been copied accurately from its source into the computer.
2. Visual checking and double data entry.
3. The computer reports the difference so the entry can be checked against the source and corrected.
4. Typing a password (or email address) twice when creating an account.
5. Transposed numbers.
6. People may miss errors through tiredness or because they see what they expect.
7. Takes about twice as long, or the same error typed twice is not detected, or source errors are not found.
8. The first line of a paragraph left alone at the bottom of a page or column.
9. Turn on widow/orphan control (or keep the paragraph's lines together), not by adding blank lines.
10. Insert a page break before the table, set the rows to stay together, or resize the table to fit.
11. An impossible value that is on the source as well, such as a month of 13, which a range check rejects but a copy check would pass because it matches the form.
12. Validation catches unreasonable data and verification catches copying errors in reasonable data; each misses errors the other finds.
