## Section A: short answers

**1.** State **two** groups of people who would use technical documentation. **[2]**

**2.** Give **three** components that appear in both technical and user documentation. **[3]**

**3.** Identify whether each item belongs in technical documentation or user documentation.

**(a)** A list of variables. **[1]**

**(b)** A troubleshooting guide. **[1]**

**(c)** System flowcharts. **[1]**

**(d)** A glossary of terms. **[1]**

**4.** State what is meant by the *limitations of the system*. **[1]**

**5.** Give **two** reasons why user documentation is written in plain language. **[2]**

## Section B: structured questions

**6.** Sunrise Travel has a new online booking system for its staff.

**(a)** Describe **three** items in the user guide that would help a new member of staff make and change bookings. **[3]**

**(b)** Explain why the user guide should include error messages and error handling. **[2]**

**7.** Two years later, Sunrise Travel employs a programmer to add a new loyalty-points feature.

**(a)** Explain why the programmer needs technical documentation. **[2]**

**(b)** Describe **three** components of technical documentation the programmer would use, and how each helps. **[6]**

**8.** Explain the difference between a system flowchart and a program flowchart. **[2]**

**9.** Both types of documentation contain the hardware and software requirements. Explain how this component might differ between the two types. **[2]**

**10.** A company is selling a home accounts program to the public.

**(a)** Explain why a frequently asked questions section would be useful. **[2]**

**(b)** Give **two** other components of the user documentation that would help customers who are installing the program at home. **[2]**

**11.** Explain why sample runs are included in technical documentation. **[2]**

**12.** Compare technical documentation and user documentation. **[4]**

## Answers

**1.** Any two of: technicians [1]; programmers [1]; systems analysts [1]; people maintaining or upgrading the system [1]. Maximum 2. **[2]**

**2.** Any three of: purpose of the system [1]; limitations of the system [1]; hardware and software requirements [1]; input format [1]; output format [1]; sample runs [1]. Maximum 3. **[3]**

**3. (a)** Technical [1].

**(b)** User [1].

**(c)** Technical [1].

**(d)** User [1]. **[4]**

**4.** What the system cannot do or the limits within which it works, for example a maximum number of records or users [1]. **[1]**

**5.** Any two of: users are not ICT specialists [1]; they need to follow instructions quickly while working [1]; technical terms could confuse them and lead to mistakes [1]; plain language reduces the need for help from support staff [1]. Maximum 2. **[2]**

**6. (a)** Any three described: how to add records, giving the steps to enter a new booking [1]; how to delete/edit records, so a booking can be changed or cancelled [1]; input format, showing which data goes in each box on the booking screen [1]; sample runs showing a complete booking from start to finish [1]; how to print data, such as a booking confirmation [1]; how to save [1]. Maximum 3.

**(b)** Users will meet error messages when entering invalid data, and need to know what each one means [1]; error handling tells them what to do to correct the problem, so they can continue without calling for help [1]. **[5]**

**7. (a)** The programmer did not build the system, so needs to know how it works before changing it [1]; this allows the new feature to be added without causing errors in existing parts [1].

**(b)** Any three, each with how it helps (2 marks each): program listing [1], showing the existing code that must be changed or added to [1]; file structures [1], showing the fields and data types stored, so a new loyalty-points field can be added correctly [1]; list of variables [1], so the programmer knows what each variable holds and does not reuse names [1]; program flowcharts/algorithms [1], showing the logic of the booking process where points are awarded [1]; program language [1], so the programmer uses the right language and tools [1]; validation routines [1], so new input rules match existing ones [1]; sample runs/test runs [1], to check the system still produces correct results after the change [1]. Maximum 6. **[8]**

**8.** A system flowchart shows how data passes through the whole system, including inputs, files, processes and outputs [1], whereas a program flowchart shows the sequence of steps and decisions within one program [1]. **[2]**

**9.** In user documentation it states the minimum computer, operating system and other software the user needs to run the system, in simple terms [1]; in technical documentation it gives more detail needed to install, maintain or upgrade the system, such as server, database and network requirements [1]. **[2]**

**10. (a)** Many customers will have the same questions [1], so answers can be found quickly without contacting the company, saving time for both [1].

**(b)** Any two of: how to load/install the software [1]; hardware and software requirements [1]; troubleshooting guide/helpline [1]; error messages and error handling [1]. Maximum 2. **[4]**

**11.** Sample runs show the output the system produces from known input [1], so after maintenance or an upgrade the technician can run the same data and check that the output is still correct [1]. **[2]**

**12.** Any four, with points about both types:
- Technical documentation is written for technicians and programmers, whereas user documentation is written for the people who use the system [1].
- Technical documentation explains how the system works, whereas user documentation explains how to use it [1].
- Technical documentation uses technical terms, code and diagrams, whereas user documentation uses plain language and step-by-step instructions [1].
- Technical documentation includes program listings, file structures and variables, whereas user documentation includes how to add, edit and print records [1].
- Both include the purpose, limitations, hardware and software requirements, input and output formats and sample runs [1].
Maximum 4. **[4]**

## Frequently asked questions

**Is a user guide the same as user documentation?**
In exam answers, yes: a user guide is a common name for user documentation.

**Do I need to learn every item?**
There are 23 different items across the two lists. You need to recognise every one and be able to name several of each type confidently. Learn the six shared items as a group, because they are a frequent trap.
