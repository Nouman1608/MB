These notes condense **section 2.4 Custom-written software and off-the-shelf software** (Topic 2 Hardware and software) of the Cambridge International AS & A Level Information Technology 9626 syllabus for 2025, 2026 and 2027. AS Level content, examined in Paper 1 Theory. Worked examples are in the [custom-written and off-the-shelf software study guide](/resources/cambridge-a-level-ict-9626-custom-written-and-off-the-shelf-software/); test yourself with the [practice questions on custom-written and off-the-shelf software](/resources/cambridge-a-level-ict-9626-custom-written-and-off-the-shelf-software-practice/).

## Key terms

| Term | Meaning |
|---|---|
| Custom-written (bespoke) software | Software written specially to meet one client's exact requirements |
| Off-the-shelf software | Ready-made software developed for a general market and sold or licensed to many users |
| Licence | Permission to use software on stated terms |
| Source code | The program as written by programmers, before translation |
| Proprietary software | Software whose owner keeps the source code secret and restricts copying and modification |
| Open-source software | Software whose source code is published and may be studied, modified and redistributed under its licence |
| Subscription | A recurring payment to keep using software |
| Maintenance | Correcting, updating and improving software after it goes live |

## Uses

- **Individuals, off-the-shelf:** word processing, photo editing, games, browsing, anti-virus, personal finance.
- **Individuals, custom-written:** rare; a sole trader's own booking app, specialised assistive software.
- **Organisations, off-the-shelf:** office suites, accounting, payroll, email, general stock control.
- **Organisations, custom-written:** airline reservations, bank account systems, national tax systems, control software for a firm's own machines.

## The four criteria: off-the-shelf versus custom-written

| Criterion | Off-the-shelf | Custom-written |
|---|---|---|
| Degree of testing | Tested by the developer and a huge user base; bugs fixed in updates | Tested only by developer and client; some errors may appear after going live; tested on the client's real processes |
| Level of support | Forums, help pages, tutorials, training courses, staff who already know it; generic | Direct, tailored support from the developer; ends if the developer stops trading |
| Cost | Low per user because development is shared; licences and subscriptions add up | High upfront: client pays all development; may avoid per-user fees |
| Adaptability | Fixed core; may lack needed features and include unneeded ones | Built to exact needs; can be changed later, at a cost |
| Time (extra) | Available immediately | Months to analyse, write and test |

## Proprietary versus open-source

| | Proprietary | Open-source |
|---|---|---|
| Source code | Kept secret | Published |
| Modify and share? | Not allowed by licence | Allowed under licence terms |
| Typical cost | Licence or subscription (some is free) | Often free of charge (paid support possible) |
| Support | Professional, from the owner | Often community-based |
| Examples | Microsoft Office, Adobe Photoshop | Linux, LibreOffice, Firefox |
| Main advantage | Polished, supported, accountable | Free, adaptable, code can be inspected |
| Main disadvantage | Cost, cannot be changed, tied to supplier | Variable support and documentation; changes need skill |

## Quick calculation pattern

Compare total cost over the same period.

- Off-the-shelf: users × licence per year × years. 30 users × £150 × 4 years = £18,000.
- Custom: development + maintenance per year × years. £12,000 + £1,500 × 4 = £18,000.
- Equal here; non-cost criteria decide. Each extra user adds £600 over four years to the off-the-shelf cost only.

## Choosing: rules of thumb

- Common task, small budget, needed now → off-the-shelf.
- Unusual processes, large organisation, competitive advantage from the system → custom-written.
- Need to inspect or change the code, low budget, in-house skills → open-source.
- Need guaranteed professional support and accountability → proprietary.

## Building a comparison sentence

Use one criterion and both options in the same sentence, then apply it:

- "Off-the-shelf software has been tested by thousands of users, **whereas** custom-written software has been tested only by the developer and client, **so** a small shop is less likely to meet bugs with a package."
- "Custom-written software can be changed when the business adds a new service, **whereas** an off-the-shelf package can only be changed by its developer, **so** a fast-changing firm may prefer custom."

## Exam traps

- "Custom software is better" with no criterion or scenario.
- Assuming custom software has no bugs.
- Equating open-source with free, or proprietary with paid.
- Ignoring ongoing costs on either side.
- Comparing on different criteria for each option, so the points never meet.
- No conclusion when the question says evaluate.

## Self-test

1. Define custom-written software.
2. Give one use of off-the-shelf software by an individual and one by an organisation.
3. Give one use of custom-written software by an organisation.
4. Why is off-the-shelf software usually well tested?
5. Why might support for custom-written software end?
6. Why is off-the-shelf software cheaper per user?
7. Explain why off-the-shelf software is less adaptable.
8. What makes software open-source?
9. Is all open-source software free of charge? Explain.
10. Give one disadvantage of proprietary software for a school.
11. A firm pays £20,000 to develop software plus £2,000 a year maintenance. What is the cost over five years?
12. Give one reason a bank might choose custom-written software for its account system.

### Answers

1. Software written specially to meet one client's exact requirements.
2. Individual: photo editing (or games, word processing). Organisation: payroll (or accounting, office suite).
3. An airline reservations system (or bank accounts, tax system, factory control).
4. It is tested by the developer and used by very many people who report bugs, which are fixed in updates.
5. The developer may stop trading or key programmers may leave, and no one else knows the system.
6. The development cost is shared across many buyers.
7. It is designed for typical users, so the client cannot change its core features to match its own processes.
8. Its source code is published and may be studied, modified and redistributed under its licence.
9. No: most is free, but companies may charge for distributions, support or services.
10. Licence costs for every computer (or the school cannot modify it, or it is tied to the supplier's upgrades).
11. 20,000 + 5 × 2,000 = £30,000.
12. Its processes are large and unusual and need high security, so no general package fits exactly.
